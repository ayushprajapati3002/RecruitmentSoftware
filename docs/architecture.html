3. Core Architectural Modules & Implementation Details

1. Pipeline State Machine Workflow

Enforces strict forward-only stage transitions: Applied ➔ Screening ➔ Interview ➔ Offer ➔ Hired. Candidates cannot skip stages or revert from terminal stages (Hired/Rejected). Backward status corruption is prevented at both the frontend UI and backend transaction levels.

2. Immutable Audit Trail (CandidateHistory)

Every promotion, rejection, or feedback note appends an immutable record to candidate_history with onDelete: NoAction. No update() or delete() methods exist on this model, guaranteeing unalterable regulatory compliance.

3. Groq Natural Language Query Engine

Conversational queries such as "Candidates with 5+ years experience in React stuck in interview for more than a week" are interpreted by Groq Llama-3.3-70B into structured filter objects with numeric thresholds, array containment, and stage criteria.

4. Parameterized Search & Ranking

Parsed JSON filters are mapped into safe Prisma WHERE clauses and raw SQL trigram similarity queries (similarity(name, query) > 0.25). Results are scored, sorted by relevance, and accompanied by transparent match explanations.

5. AI Collaboration & Technical Disagreement Case Study

Technical Disagreement: Rule-Based Offline Regex vs. Pure LLM Intent Parsing

The AI Assistant's Proposal: During search implementation, the AI initially proposed a dual-tier approach featuring "Step 1: Offline Rule-Based NLP" using regex patterns (e.g. /(applied|screening|interview|offer|hired)/i, /(\d+)\+?\s*years?/i) before delegating to the LLM.

"Don't want this Step 1: Offline Rule-Based NLP. Remove the changes of step 1 only." — Engineer Direction

Why the Engineer Disagreed & Overruled the Proposal:

  • Brittle Semantic Interpretation: Natural recruiter questions like "candidates who did screening in frontend" easily fool keyword matching (mistaking "screening" as candidate notes instead of stage status).
  • Codebase & Maintenance Duplication: Maintaining an offline regex grammar alongside an LLM adds duplicate logic, conflicting edge cases, and high testing overhead.
  • Inference Speed Reality: Because Groq executes Llama-3.3-70B in <250ms, a fragile offline regex fallback was completely redundant. Pure LLM extraction with deterministic schema output is cleaner and far more resilient.

6. Security, Reliability & Data Integrity

SQL Injection Prevention

All database queries are executed via Prisma ORM parameterized methods or tagged template literals (prisma.$queryRaw`...`). Raw, unescaped string concatenations are strictly forbidden across the codebase.

Soft Deletion Safeguards

Candidates are never hard-deleted from PostgreSQL. The isArchived = true flag prevents active pipeline clutter while permanently retaining candidate contact records and audit history.

CORS & API Environment Isolation

Dynamic CORS policy permits authorized client domains. Sensitive database credentials and Groq API tokens are stored in environment variables, never committed to version control.

Transaction-Atomic Stage Moves

Every candidate status update is wrapped in a PostgreSQL database transaction (prisma.$transaction), ensuring that candidate updates and audit history inserts either both succeed or both roll back.
